# Client/job application SOP

## Before spending
1. Confirm open listing and eligibility (South Korea, remote, communication mode).
2. Validate client payment history only when actually visible; never invent it.
3. Check exact requested format and required screening phrases; any odd third-party contact, payment or free full-project test is red flag.
4. Check AI-assistance policy; if absent, plan compliant disclosure/permission without leaking files.
5. Estimate total scope/hours and quote; compare to USD 17/hr profile baseline, fee, rework and currency costs.
6. Confirm Connects required; user approves any spend.

## Per-client deliverable packet
- 4–8 sentence tailored proposal with first sentence answering the brief.
- Link to a matching, verified GitHub project and a sanitized demo.
- Explicit scope, timeline assumptions, acceptance test, communication format and revisions.
- One focused question only if critical.
- Loom/job-specific format if required, 1–2 minute verified playback.
- Personal credentials truthful: Economics BA (2015), KDT attended Aug–Oct 2026, independent engineering projects, no paid history invented.

## After decision
Update LEADS with status and source, STATUS and HANDOFF; only mark `APPLIED` after user submits and proof exists. Never create fake testimonials.

## Delivery gate
Run local tests on actual customer-approved data; make sure rights/privacy and license allow. Confirm reproducibility, format, data redaction and client sign-off. Record dispute/rework scope before payment is considered earned.
