# BID AX — P85 기술 단계 수용 기록 (2026-11-13 KST)

**사용자 목표:** 최종설계 전체 85%. **독립 판정:** 오프라인 데이터 복구·검증·배포 절차의 P85 *부분 기술 범위* 로컬 PASS; 공식 최종완성률 `UNASSESSED`, `[작업중]` 유지, `RELEASE HOLD`·크몽 미등록. 21개 최종설계 요구 및 출시 게이트 축소 없음.

## 기능·보안 변경

- `bidax/batch.py`: 로컬 공식형 JSON 스냅샷을 UUID 배치/카테고리/조회기간(<=7일)/페이지 수로 구획, SHA256 체크, 순서 무관 페이지 저장, 중간 재시작 복구. 모든 페이지/총건수가 맞을 때만 기존 `BidLedger.ingest`에 승격. 충돌/누락/페이지 조작은 거절, 완료 배치 재실행은 중복 없음. `snapshot_pages` 저장은 로컬 SQLite이며 원본 API 공식 필드 검증이 끝난 게 아님.
- `bidax/reminders.py`: 사용자가 앱/CLI에서 명시적으로 실행하는 마감 알림 조회. 동일 공고 버전·상태·조회기간의 중복 이벤트는 SQLite에 기록해 방지. 컴퓨터가 꺼져 있거나 앱이 실행되지 않을 때 자동 알림을 전송하지 않음.
- `bidax/transport.py`: **제품 CLI·GUI와 연결하지 않은 실 API 전송 라이브러리 준비**. 호출자가 `permission=True` 및 고객 소유 키를 명시적으로 넣어야 함. 공식 호스트/경로 고정·재지정 거절, 10MiB 상한, 최대 3회 제한/대기, 하루 최대 1,000회 설정 범위 안에서 로컬 시도 횟수 차감(실 운영 quota와 별도), 응답 JSON 중복 키·비JSON 거절. 테스트는 주입된 가짜 전송만 사용. 실제 정부 API 요청 **0건**. 키 저장/로그 없음. 한도 산정·정책·원문 매핑은 고객/공식 검증 전 미완성.
- `bidax/cli.py`: `stage-page`, `stage-status`, `poll-alerts` 로컬 명령 추가. `bidax/desktop.py`: 마감 알림 버튼을 저장되는 중복 제거 조회로 전환.
- `packaging/`: Windows 3.11 설치 없이 수동 PyInstaller 구축 스크립트, 앱 엔트리, 소스 ZIP allowlist+SHA256 manifest. Windows 바이너리/설치파일은 아직 빌드·검증되지 않았음. EXE를 판매/서명 배포하지 않음.
- 보존: 기존 P70 GUI·CLI·원본 21요구·소스·SQLite·타 상품·제외된 BID OWL. 새 기능 자동 크롤링/자동 입찰/고객 데이터 외부 전송 없음.

## 전체 최종설계 R01~R21 잔여 게이트

- R01-R04: 공식 운영 이용조건·API 실제 필드/원문/첨부 실사, 고객 키 계약·실제 성공/429/5xx 호출 및 알림/수집 제한. **미검증**.
- R05-R07: 로컬 계약·SHA 버전·SQLite·체크포인트 회귀 일부 검증, 현장 실원문·물리 PC 복구 검증 **미검증**.
- R08-R11: 기업/면허/제출서류 규칙은 합성 로컬 선별에 국한, 실제 법적 자격/원본 첨부 대조 **미검증**.
- R12-R15: KST 마감·수동 조회·보고서 JSON/CSV/HTML/수동 이력 부분 검증. 백그라운드 스케줄·실 PDF·역할 인증·수집 변경 자동 알림 **미구현**.
- R16-R18: Tk GUI는 Linux 가상 화면 일부 검증. Windows10/11 정식 설치/제거/서명·암호화 키 저장·고객 데이터 접근제어 **미검증/미구현**.
- R19-R21: 실제 공고100건·자격10건 독립 대조, 최종 법률·계약·고객 수락·판매 승인 **미검증**.
